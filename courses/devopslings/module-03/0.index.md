## What you'll be able to do

- Grow a volume and its filesystem, in the right order, on a live service
- Write an `/etc/fstab` entry that survives a device being renumbered
- Recognise CPU throttling on a box that appears to have spare CPU
- Tell a saturated disk from a busy one, and know why `%util` does not say
- Separate page cache from a real leak with evidence rather than a restart
- Size a volume from a growth curve instead of from the last incident

## Why these

Every one of these has a plausible reading that is wrong, and the wrong reading
is the one the obvious tool encourages. `df` says free. `top` says idle.
`iostat` says 100%. Memory says the application is growing. In each case the
number is accurate and the story people build from it is not.

That gap — between a true measurement and a false conclusion — is where most
capacity incidents actually live, and it is the reason this module sits before
performance work rather than inside it.

## Before you start

Modules 01 and 02. This module runs `linux-box` with loop devices and LVM, so
the sandbox needs a little longer to set up each scenario than earlier lessons.

A note on scope: a container shares its kernel with the host. Swap and the
`vm.*` and `kernel.*` sysctls are machine-wide, so the exercises here work
inside cgroups and on loop-backed volumes, which are genuinely per-container.
Where a lesson simulates something it cannot own, it says so.
