## What you'll be able to do

- Move a secret out of an image and into a secret store, so it is in no file,
  no layer and no environment
- Write a policy per service, and prove the paths it should not read are denied
- Replace a shared database password with leased credentials, and revoke one
  service without touching the others
- Keep encrypted secrets in git with SOPS and age, and let CI decrypt them
  with its own key
- Audit a small estate for secrets, including the ones not in obvious places
- Rotate a credential under load, with a dual-read window and zero failed
  requests
- Handle a leaked token to the end: revoked, and verified from the attacker's
  side

## Why OpenBao and not Vault

HashiCorp moved Vault to the Business Source License in August 2023. OpenBao is
the Linux Foundation fork from before the change, under MPL-2.0. The CLI is
`bao` instead of `vault`, and the API, the policies and the secrets engines are
the same. Everything here transfers to Vault.

## Before you start

The stack is `ci-stack`, and OpenBao and a Postgres database run alongside the
forge. OpenBao is a real server, not dev mode. It is initialised once and
unsealed whenever it starts, so what you store survives a restart.

- OpenBao: <http://localhost:8200/ui>, root token `devopslings-root`
- The `bao` CLI is inside the `bao` container. This function lets you run it
  from anywhere:

```
bao() { docker exec -i -e BAO_TOKEN="${BAO_TOKEN:-devopslings-root}" devopslings-ci-stack-bao-1 bao "$@"; }
```

The root token can do anything, which is right for you as the operator and
wrong for any service. The lessons show the difference.
