## What you'll be able to do

- Write a Pulumi program in Go and take it through up, preview and destroy
- Tell what the compiler checks from what only the provider can check
- Move resources that OpenTofu manages under Pulumi without recreating the
  ones that hold data
- Build different topologies from one config value with ordinary `if` and
  `for`
- Run dev and prod from one program, with a secret that is never stored in
  plaintext
- Write a unit test that fails on a public bucket before anything is created
- Choose between Pulumi, OpenTofu and neither, for reasons you can state

## Why these

Pulumi is often sold as "Terraform, but in a real language." That is true,
and it leaves out what changes. The state model, the plan and the providers
are much the same. What is new is the program around them. Each lesson is one
thing that program can do that HCL cannot, or one way it makes a mistake
easier to make.

## Before you start

Module 13 (OpenTofu). This module runs the same `iac-stack`, which also has
Go 1.26, the Pulumi CLI, and the docker and minio providers. Programs build
offline from a module cache in the image. State lives in a local backend, so
no Pulumi Cloud account is involved. Stacks use a passphrase secrets
provider, and the passphrase is already in `PULUMI_CONFIG_PASSPHRASE`.
