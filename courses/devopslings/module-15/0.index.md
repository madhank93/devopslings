## What's different about grading here

Lessons in this module declare an `inject_fault` step that runs **after** your
work and **before** the check. You are not graded on the end state of a broken
system; you are graded on how the system you configured behaves once something
goes wrong under it.

You will see a note when you start such a lesson. The fault is never a surprise
and never a trick — the point is to design for a failure you have been told
about, which is the only kind anyone ever gets to design for.

Checks in this module are k6 load tests. k6's `thresholds` exit non-zero on
breach, so the load test *is* the grade — there is no wrapper interpreting it.

## What you'll be able to do

- Set timeouts that bound the worst case rather than the happy path
- Tell the difference between failing fast and failing well
- Recognise a retry storm before you cause one

## Before you start

`chaos-stack` builds two small Python services and pulls toxiproxy and k6.
First run takes a couple of minutes; after that it starts in seconds.
