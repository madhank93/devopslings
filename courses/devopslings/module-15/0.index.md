## What you'll be able to do

- Point one command at a group of hosts and know whether every host answered,
  including the ones the inventory quietly left out
- Write a playbook that takes a clean box to a serving web server in one run
- Get a second run to report `changed=0` without hiding real changes from it
- Make a config change reach the running service through a handler, and only
  when the config actually changed
- Turn a one-off playbook into a role that passes a molecule test from a clean
  machine
- Keep a password out of plain-text vars with Vault, and use `become` only
  where a task needs root

## Why these

A configuration tool is a promise that the box matches the description. Each
lesson here is a way that promise breaks without an error: a host that was
never asked, a playbook that only works on the box it was written on, a run
that reports change every time so a real change goes unnoticed.

## Before you start

Module 02, especially idempotent-by-construction. This module runs
`linux-box` with `ansible-core` installed. Where a lesson needs a fleet, it is a
set of SSH servers on that one box, each with its own name and port, so a dozen
hosts cost almost nothing to run.
