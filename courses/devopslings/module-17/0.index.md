## What you'll be able to do

- Run a workload on a role instead of a key, and retire a leaked key properly
- Narrow a `*` policy to what the application does, and prove the rest is
  denied
- Tell a role's trust policy from its permission policy, and fix the right one
- Close every route by which an S3 object is public, and share one file with
  a link that expires
- Explain why a network ACL drops a reply a security group would have let
  through
- Give a private subnet a way out that is not a way in
- Recover a deleted object from its versions, and bound what old versions cost
- Find where an unexplained bill increase came from, and say what each fix saves
- Make a buy or build call that states its downside

## Why these

Identity, storage and network misconfigurations are the three that keep
appearing in breach reports. Each lesson starts from the plausible first fix,
the one that makes the symptom go away, and grades the one that closes the
hole.

## Before you start

Module 13 (OpenTofu) for the sandbox. This module runs `iac-stack` with the
`aws` CLI pointed at floci. floci denies any call no policy allows, and treats
an unsigned S3 request as anonymous, as AWS does. Two things it does not do:
it stores network rules without moving packets, and it stores S3 Block Public
Access settings without enforcing them. Where a lesson depends on either, the
grader evaluates your configuration as AWS would and says so.
