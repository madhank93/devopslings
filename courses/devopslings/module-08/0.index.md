## What you'll be able to do

- Land a branch on main so the history records that it was a branch, and know
  what the default fast-forward leaves out
- Find the exact commit that introduced a regression with `git bisect`, in a
  handful of steps rather than a linear scan
- Recover a branch after a `reset --hard` using the reflog
- Remove a secret from history and understand why removal is not enough on its own
- Reason about when rebase and when merge is the safe choice
- Read what `--no-verify` actually skips before you type it

## Why these

Version control failures are recoverable far more often than they feel, and the
recovery is a specific command, not a guess. The cost of not knowing it is
either lost work or a destructive "fix" that loses more. Each lesson here is one
of those moments — the branch is gone, the secret is committed, the bug is
somewhere in two hundred commits — met with the operation that resolves it.

## Before you start

No sandbox — these lessons run in a throwaway git repository on the host. You
need git installed; everything else the lesson builds for you.
