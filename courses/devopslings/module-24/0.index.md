## The stack

Most lessons run on `ha-stack`, the same shop as modules 22 and 23:

```
                 www = 172.29.22.100 (a VIP)
                          │
              lb1 ────────┴──────── lb2        HAProxy + keepalived
                 └──────┬───────┬──────┘
                      web1     web2            the shop, twice
                 ┌──────┴───┬───┴──────┐
                pg1  ───▶  pg2      etcd1 etcd2 etcd3
```

You work in `ops`. The data each lesson reasons about — a day of lb1's log,
thirty days of request counts, an incident timeline — is under `/ha/sre`, and
written answers go in `/ha/answers`. `node`, `gapwatch` and `lbctl` work as
they did in module 22.

The alerting lesson runs on `obs-stack`, module 18's Prometheus, because
burn-rate alerts are Prometheus rules and are tested with `promtool`.

## What you'll be able to do

- Choose an indicator that moves when customers hurt and stays flat when they
  do not
- Compute an error budget in requests, and how much of it an incident spent
- Write burn-rate alerts that page for a fast burn and open a ticket for a
  slow one
- Tell which of RED, USE and the golden signals answers the question in front
  of you
- Automate a weekly chore so that it runs, reports, and is safe to run twice
- Reject a canary on the metric that moved, automatically
- Roll back in seconds with a schema both versions can use
- Turn a feature off without a deploy, and clean up the flags nobody needs
- Run an incident with roles that hold, and a commander who does not debug
- Size a fleet from measured service times, and name what saturates first
- Write an error-budget policy the team can actually enforce
- Run a chaos experiment with a bounded blast radius and an honest conclusion
- Write a blameless postmortem whose actions have owners
