## What you'll be able to do

- Describe a running container in HCL and take it through plan, apply and
  destroy as many times as you like
- Read what state holds, and fix it with `state mv`, `state rm` and `import`
  instead of an editor
- Stop two applies from writing the same state at once
- Find drift with a plan, put it right, and catch the next one in CI
- Remove one item from a list without touching its neighbours
- Bring infrastructure that predates the code under management without
  recreating it
- Move state off a laptop into a shared backend without losing a resource
- Make a plan that would delete data fail before anyone has to read it

## Why these

Writing the first resource takes ten minutes. What takes years to learn is
what a plan will do to things that already exist. Each lesson here is a plan
that looks routine and would destroy, recreate or forget something real.

## Before you start

Module 05 (Docker). This module runs `iac-stack`: a workstation with
OpenTofu 1.13 and a docker CLI, a Docker daemon of its own for OpenTofu to
manage, and MinIO for shared state. Nothing you destroy here can reach the
host. Providers are installed from a local mirror, so `tofu init` works
without the network.
