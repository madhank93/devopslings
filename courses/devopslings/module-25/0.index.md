## What you'll be able to do

- Count deployments and say what counted, so next quarter's number is
  comparable
- Make a pipeline emit one deployment event per successful deploy, with its
  commit and its own time
- Measure lead time per change and report it as a distribution
- Compute change failure rate and Failed Deployment Recovery Time under the
  2025 definitions, excluding failures no change caused
- Find rework deployments from the history, including the ones nobody filed an
  incident for
- Spot a metric that was pushed, and name the counter-signal that would have
  caught it
- Place a team in one of DORA's seven archetypes from its data, not its speed

## The sandbox

`ci-stack`, the forge from module 12. Each lesson seeds `devops/checkout` with
a deterministic history: twelve weeks of commits on `main`, plus the tags the
pipeline left behind. Deployments are annotated tags
`deploy/<environment>/<run>`, and their messages say what happened.

```
git clone http://devops:devopslings@localhost:3000/devops/checkout.git
```

Answers go in `scratch/<lesson>/answer.txt`, a template the lesson writes when
it starts. The checks recompute every number from what is on the forge.

## Before you start

Module 12 for the pipeline, and enough `git` to read tags and walk history:
`git tag -n9`, `git for-each-ref`, `git rev-list A ^B`, `git log --format`.
Everything here runs in a shell with `awk` and `sort`; no other tools are
needed.
