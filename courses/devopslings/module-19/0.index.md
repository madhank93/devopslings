## What you'll be able to do

- Decide which parts of a log record become labels and which stay in the
  line, and see the cost of getting it wrong in a query's own statistics
- Read and repair an OpenTelemetry Collector pipeline: receivers, processors
  in the order they run, exporters
- Reshape records with OTTL and with VRL, and prove field by field that
  nothing else changed
- Give an OpenSearch index a mapping that cannot grow without bound
- Carry trace context across a queue, and link a latency histogram to the
  trace that explains its tail
- Find where a pipeline drops data, and alert on it

## The sandbox

The same `obs-stack` as module 18, with logs and traces added: Loki, Tempo,
an OpenTelemetry Collector, OpenSearch, and some services that log and trace.
checkout publishes orders to broker, an in-memory queue; fulfil takes them off
it and records each with ledger. billing logs every invoice to the Collector.

You work in the `box` container. Everything you edit is under `/obs`:

| Path | What |
|---|---|
| `/obs/otel/collector.yaml` | the Collector's config; saving it restarts the Collector |
| `/obs/vector/` | Vector configs and VRL programs |
| `/obs/apps/*.py` | the services' source; saving a file restarts that service |
| `/obs/logs/*.log` | each service's output, the Collector's included |
| `/obs/queries/`, `/obs/answers/` | queries and written answers the checks read |
| `/obs/opensearch/` | tickets for the OpenSearch index, and what it refused |

Tools on the PATH: `logcli` (Loki's CLI, already pointed at Loki), `vector`,
`promq`, `promtool`, `obs-reload`, and `ticket-ship`, which indexes support
tickets into OpenSearch. From your browser: Grafana at
<http://localhost:13000> has Prometheus, Loki and Tempo datasources. Loki is at
<http://localhost:13100>, Tempo at <http://localhost:13200> and OpenSearch at
<http://localhost:19200>.
