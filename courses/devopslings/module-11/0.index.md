## What you'll be able to do

- Say exactly what a tag names and what a digest names, and pull by either
- Pin a deployment so a re-pushed tag cannot change what runs
- Write a retention policy that frees space without deleting your rollback
- Sign an image, and make the runtime refuse one that is not signed
- Run a CVE gate that has exceptions, and make the exceptions expire
- Pin a base image so an upstream push cannot change your build
- Stop an internal package name from resolving to a public impostor
- Give each consumer of the registry exactly the access it needs
- Reconstruct a supply-chain compromise and the controls that would have caught it

## Why zot and not Harbor

Harbor is the open-source registry the roadmap's Artifactory slot points at,
and it is the one you are most likely to meet at work. It is also around nine
containers and ships amd64 images only. The sandbox runs
[zot](https://zotregistry.dev), a single multi-arch container implementing the
same OCI distribution API, with the features these lessons grade: per-repository
access control, retention policies, and the referrers API that signatures and
SBOMs attach to. Where Harbor names a feature differently, the lesson says so.

## Before you start

```
devopslings start push-your-first-image
```

You land in `workstation`, a box with `docker`, `crane`, `skopeo` and `cosign`.
The `docker` CLI drives your host's daemon, so builds and pushes behave as they
do on your laptop. The registry is `127.0.0.1:15000` from the box and from your
host alike — log in as `devops` / `devopslings`.
