## What you'll be able to do

- Wire a command's exit status to a build's colour, and prove red is reachable
- Write a workflow from scratch and debug it when the runner disagrees with you
- Recognise a pipeline that is green for the wrong reason
- Write a cache key that is true, so a changed dependency is not hidden by it
- Handle a leaked secret correctly, which is not "delete the log"
- Tell a flaky shard from a broken one, and gate a merge on the difference
- Promote one artefact through every environment, instead of rebuilding it
- Read a branch protection rule for the doors it leaves open, and close them

## Why Forgejo and not GitHub Actions

GitHub Actions is the roadmap's recommendation and it is not open source, so it
cannot be the thing you run locally. Forgejo Actions executes the same workflow
YAML through `act_runner`. The syntax you learn here — `on:`, `jobs:`,
`runs-on:`, `steps:`, `uses:`, `with:`, `secrets` — is the syntax you will write
at work.

Where the two genuinely differ, the lesson says so.

## Before you start

`ci-stack` is the heaviest sandbox in the repo: a forge, a runner, and a
registry. First start pulls roughly 400 MB and takes a few minutes; after that
it comes up in under a minute. Give Docker at least 4 GiB.

```
devopslings start first-pipeline
```

The forge is at <http://localhost:3000> — log in as `devops` / `devopslings`.
