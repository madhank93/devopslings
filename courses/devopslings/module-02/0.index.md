## What you'll be able to do

- Write a loop that survives a filename with a space, a newline or a leading dash in it
- Tell whether a pipeline actually succeeded, rather than whether its last stage did
- Name the four contexts where `set -e` is silently suspended, and handle each
- Make a script that can be run twice, or interrupted half way, without damage
- Clean up after yourself on every exit path, including the ones you did not plan
- Know when a shell script has stopped being the right tool, and say why

## Why these

Shell is the only language most people learn entirely by copying. That works
until the script is scheduled, and then every assumption it quietly made — that
filenames are words, that `$?` means the pipeline, that `set -e` catches
everything, that it will only ever run once and to completion — becomes an
incident with nobody at the keyboard.

The failures here are not exotic. They are the ordinary ones, and they are
ordinary precisely because the code looks correct and passes the only test it
ever gets: the author running it by hand, once, on files they named themselves.
